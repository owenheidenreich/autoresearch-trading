# Protocol101 Data Expansion Approval Request Draft

## Purpose

Request owner review for Protocol101 historical data expansion choices under the synchronized live-reproducible game.

This request is for data provisioning only. It does not authorize model training, threshold tuning, promotion/default changes, paper-submit, broker orders, or real-money trading.

## Current Finding

The project is no longer blocked from the first fair-contract diagnostics fold program by a new data purchase.

The vendor inventory found owned local raw data from approximately:

```text
2024-10-01 through 2026-07-02
```

with overlapping Databento OPRA option products and ThetaData SPX/VIX index bars across the same raw session universe. The processed `protocol101-live-v1` rows currently cover only the already-used July 2025 through March 2026 area.

Implication:

```text
Option A costs $0 in new vendor spend:
process owned Oct 2024-Jun 2025 raw data first,
run acceptance gates,
then run the first rolling diagnostics folds.
```

The purchase decision therefore changes from:

```text
new data is required to unblock the program
```

to:

```text
new data upgrades the evidence from adequate to more decisive.
```

## Acceptance Criteria

Data is not accepted merely because files exist or were downloaded. It is accepted only after:

- per-session coverage reports exist;
- no-label-minute rates are inside the predeclared tolerance or explicitly blocked;
- ladder-size distributions are inside expected bounds;
- DB-vs-ThetaData/context field-diff sample runs on the stratified sample where fields exist;
- label recompute spot-checks pass;
- session hash manifests exist;
- corrupted, duplicated, or missing sessions are repaired or excluded with reasons;
- total cost and storage are recorded against the approval cap.

If these gates fail, the outcome is vendor/data remediation, not model evaluation.
