# Protocol101 Backfill Approval Request Draft

## Purpose

Request owner approval for the paid historical data backfill needed to evaluate Protocol101 fair-contract folds under the synchronized live-reproducible game.

This approval request is for data provisioning only. It does not authorize model training, threshold tuning, promotion/default changes, paper-submit, broker orders, or real-money trading.

## Why This Is Needed

The March 2026 diagnostic packet showed that the current fair-contract pocket does not have enough evidence to justify training or paper-submit. The next valid step is a broader chronological fold set. That requires more historical SPXW 0DTE + SPX/VIX context data built under the same `protocol101-live-v1` feature contract and `protocol101_serial_simulator_v2` replay semantics.

Without this backfill, the project remains stuck using a small/burned March diagnostic window and cannot distinguish:

- a genuinely dead strategy pocket,
- a pocket with learnable structure that only appears across regimes,
- a sampler/timing problem,
- or a model/label design problem.

## Requested Scope

Minimum useful backfill:

```text
2024-01-02 through 2026-03-31
```

Target backfill:

```text
2023-01-03 through 2026-03-31
```

Data scope:

- Databento OPRA SPXW 0DTE definitions.
- Databento OPRA SPXW 0DTE quotes/CBBO/OHLCV/statistics as required by the existing historical builder.
- ThetaData SPX one-minute index bars.
- ThetaData VIX one-minute index bars.
- Any existing manifest/provenance artifacts needed to make every session traceable to vendor, schema, date, symbols, and download parameters.

Exact schemas and symbols should be generated by the existing project manifest/download tooling, not ad hoc shell commands.

## Required Deliverables

For every included session:

- raw vendor files preserved;
- processed `protocol101-live-v1` decision rows;
- labels for policies `{0, 1, 2}`;
- session hash manifest;
- coverage report;
- no-label-minute report;
- ladder-size distribution;
- data-quality blockers;
- source/provenance metadata.

Backfill-level deliverables:

- manifest of included sessions;
- era tag per session:

```text
virgin_pre_jul2025
model_train_era_jul_dec2025
burned_mar2026
confirmation_jun_jul2026
```

- coverage summary by month;
- DB-vs-ThetaData/context field-diff sample plan;
- label recompute spot-check plan;
- storage usage summary;
- estimated vendor cost summary.

## Governance Restrictions

Approved use:

- data foundation;
- coverage/quality checks;
- fold orchestration;
- gate/null diagnostics;
- sampler comparison;
- label/feature builder validation;
- eventual owner-approved training only after preregistered fold gates pass.

Not approved by this request:

- live broker connectivity;
- IBKR paper-submit;
- real-money trading;
- model training;
- threshold tuning;
- promotion/default changes;
- paid downloads outside the approved dates/scope;
- using burned March or June/July recorder sessions as fresh model evidence.

## Evaluation Plan After Backfill

1. Build live-style historical rows under `protocol101-live-v1`.
2. Verify `protocol101_serial_simulator_v2` metadata in all replay artifacts.
3. Run coverage and label spot checks before any model evaluation.
4. Run rolling folds:

```text
train 128 sessions -> embargo 5 sessions -> test 21 sessions, step 21
```

Minimum evidence:

```text
at least 8 folds
at least 150 pooled out-of-fold trades per strategy row
```

5. Compare only the frozen sampler menu:

```text
first_eligible
dwell_2
slot_schedule_3win
Null-U
Null-M
future model candidate as sixth sampler only after training is separately approved
```

6. Authorize model training only if the pre-registered pocket bar passes.
