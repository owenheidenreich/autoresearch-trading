**Pre-fold pin: separate the three hash purposes.** As implemented, `simulator_semantics_hash` is computed over the semantics dict *after* `candidate_stream_hash` has been inserted, so two runs with identical simulator configuration but different candidate streams get different semantics hashes — which defeats the "compare one string to confirm same replay rules" purpose. Meanwhile `candidate_stream_hash` covers only decision keys (split/session/time/contract/right/offset), not `entry_ask`/`raw_label_pnl`. That key-only property is actually *valuable* — it makes cross-vendor paired replays of the same decisions hash-equal, which is exactly what you want for pairing — but it means a relabeled dataset fed through the same keys is invisible to the hash. Restructure into three fields with declared purposes: `simulator_config_hash` (config-only semantics — answers "same rules?"), `candidate_stream_hash` (key-identity, vendor-independent — answers "same decisions?", keep as-is), and a new `candidate_payload_hash` (keys + ask + label + cooldown — answers "same data?"). Fix this before fold artifacts exist, because artifacts written under the current conflated hash can't be retro-compared once the definition changes.

**Second pre-fold item: forced-flat truncation.** Entries are cut at 15:30, but policy 2 holds 45 minutes — an entry at 15:29 would carry `synthetic_exit_time` ≈ 16:14, past the contract's `forced_flat_before = 15:55`. The account-state consequences are nil today (the cutoff blocks any later same-session entry, and end-of-stream flush realizes the pending), but the trade record asserts an exit time live would never produce. Cap `synthetic_exit_time` at 15:55 ET, add `forced_flat_before` to the semantics block, and — this is the important half — `VERIFY:` that the label pipeline truncates the policy-2 hold at 15:55 when computing `labels_net_pnl` for late entries. If it doesn't, late-afternoon policy-2 labels encode holds live can't take, which is a label-pipeline bug independent of the simulator. Guardrail #11 says it must; one spot-check per policy confirms it.
