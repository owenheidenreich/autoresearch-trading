### 2. Model integrity check logs but doesn't block promotion

**File:** `tools/inner_loop.py` lines 504-519

When a model is promoted (KEEP), the code checks whether the embedded score in the checkpoint matches the reported score. Three failure modes are silently swallowed:

- Embedded score diverges >50% from reported → logs error, **promotes anyway**
- `torch.load()` fails entirely → logs warning, **promotes anyway**
- Checkpoint has no metrics field → silently ignored, **promotes anyway**

**Fix:** If integrity check fails, skip promotion and REVERT. A model with unknown integrity should never become `best_model.pt`.

## MEDIUM — Fix Soon

### 4. Three-file promotion is not atomic

**File:** `tools/inner_loop.py` lines 521-523

Promotion writes three files sequentially:
```python
shutil.copy2(tmp_model, BEST_MODEL_PT)    # 1. model
shutil.copy2(TRAIN_PY, BEST_TRAIN_PY)     # 2. code
BEST_SCORE_FILE.write_text(str(score))     # 3. score
```

A crash between any two lines leaves `best_model.pt`, `best_train.py`, and `.best_score` out of sync. The operating manual (Section 8) calls this the "key invariant" — but the code doesn't enforce it atomically.

**Fix:** Write `.best_score` to a temp file and `os.rename()` (atomic on POSIX). Or add a `.promotion_in_progress` sentinel that gets checked on startup.

### 5. PBT re-training winner may not reproduce

**File:** `tools/inner_loop.py` lines 1166-1238

When a PBT member wins, the code re-trains from scratch with the same config to get a downloadable model file. But training is stochastic — the re-run may produce a significantly different score. Divergence is logged but promotion proceeds regardless.

**Fix options:**
- Download the actual PBT-run model instead of re-training (saves GPU time too)
- Or reject promotion if re-trained score diverges >15% from original

### 7. Silent exception swallowing in multiple places

Several `except` blocks catch errors and return None or pass, making it impossible to distinguish "file missing" from "file corrupted":

| Location | What happens | Risk |
|----------|-------------|------|
| `art2.py` `read_json()` (line 163) | Bare `except: return None` | Corrupted JSON looks like missing file |
| `inner_loop.py` `.best_score` parse (line 278) | `except: pass`, falls to -5.0 | Corrupted score silently resets baseline |
| `art2.py` spend tracker (line 208) | `except: pass` | Corrupted tracker resets history |

**Fix:** Replace bare excepts with `log.warning(f"...: {e}")` at minimum. For `.best_score`, log the file contents so you can see what went wrong.
