# Honest End-to-End V2 Plan for SPX 0DTE Paper Trading

## Summary
Replace the current “optimize a leaky replay score forever” loop with a staged system that first makes offline evaluation honest, then makes promotion reproducible, and only then enables autonomous paper trading. The plan assumes:
- End state is v2 autonomous paper trading, not just a research loop
- `Tier 3` oracle labels become the standard dataset
- The promotion score is redesigned now around a fixed-bankroll account curve

## Key Changes
### 1. Data and evaluation contract
- Rebuild `v2/data.pt` with `Tier 3` labels only. Positive labels must vary across strike offset, stop, target, and hold; add a hard dataset-quality gate that fails if any of those remain degenerate.
- Replace the inherited 2-way split with 4 date-only masks in the dataset:
  - `train_mask`: all historical dates except recent evaluation windows
  - `val_mask`: the 60 trading days before promotion
  - `promote_mask`: the next 60 trading days used for keep/revert
  - `shadow_mask`: the last 20 trading days, never used for keep/revert
- Extend dataset metadata/fingerprints to include split boundaries, label tier, oracle search grid, evaluator fingerprint, and candidate-universe version.
- Keep the current trading universe for this plan as the existing SPXW `ATM +/- 30` point range in `5`-point steps, calls and puts, `1` contract max.

### 2. Promotion score redesign
- Stop using per-trade percentage metrics as the primary ranking signal.
- Replay must compute dollar P&L per trade using `qty * 100` contract multiplier, then build a daily equity curve from a fixed starting equity of `$50,000`.
- Add daily/account metrics to replay output:
  - daily P&L
  - daily return
  - traded days
  - positive-day rate
  - max account drawdown
  - net P&L dollars
  - failure reason when a gate fails
- Promotion gates on `promote_mask`:
  - at least `30` trades
  - at least `15` traded days
  - minority direction share at least `15%`
  - max account drawdown at most `20%`
  - deterministic replay
  - beats all three baselines on both score and net P&L
- Ranking score for gate-passing models:
  - `score = min(daily_sortino, 6.0) * positive_day_rate * dd_mult`
  - `dd_mult = 1.0` at `<= 8%` drawdown, then linear decay to `0.0` at `20%`
- `shadow_mask` is not used for keep/revert. It is only evaluated for session leaders and for models being considered for live paper rollout.

### 3. Reproducibility and mutation boundary
- Introduce a shared typed policy object, for example `DecisionPolicy`, used by train, replay, and live.
- Move all materially trade-shaping constants out of ad hoc code and into that policy:
  - gate threshold
  - risk output ranges
  - cooldown
  - time blocks
  - candidate filters
  - order style
  - exit policy
  - daily loss cap
- Make exactly two mutable research surfaces:
  - model/training logic
  - shared policy spec
- Replace loose checkpoint loading with artifact bundles. Each kept experiment must persist:
  - checkpoint weights
  - model spec
  - policy spec
  - dataset fingerprint
  - evaluator fingerprint
  - score fingerprint
  - git SHA
  - train-source snapshot
- Replace `load_model()` with artifact loading that reconstructs from saved spec and hard-fails on mismatch instead of silently instantiating current defaults.

### 4. Live paper-trading cutover
- Build `v2/live` around the same `TradeIntent` path and shared policy used in replay. No live-only thresholds or rescue logic.
- Required live capabilities before scheduled paper mode:
  - market-data stream and feature parity
  - intent generation using the same policy surface as replay
  - bracket execution lifecycle
  - reconnect recovery
  - orphan detection
  - kill switch
  - daily loss limit
  - EOD flatten
  - audit log
- Rollout sequence:
  1. Offline pass on `promote_mask`
  2. Shadow evaluation on `shadow_mask` for session leader
  3. Five intent-only shadow sessions with live data and no orders
  4. Three full autonomous paper sessions with orders
  5. Only then enable scheduled autonomous paper mode

### 5. Research loop and ops
- Do not implement `LOOP FOREVER` first. Re-enable autonomous experimentation only after the offline contract above is in place.
- `run_experiment` must:
  - train on `train_mask`
  - choose checkpoint on `val_mask`
  - score on `promote_mask`
  - compare to cached baselines
  - persist the artifact bundle and manifest
- `inner_loop` must enforce hard session limits again:
  - `6` hours max
  - `50` experiments max
  - `8` no-improve streak
  - `3` hour plateau
  - `3` consecutive crashes
- `monitor` should show split-specific metrics, baseline deltas, artifact fingerprints, session leader, shadow status, and live-readiness status.

## Important Interface Changes
- Dataset adds `promote_mask`, `shadow_mask`, and richer split metadata.
- Replay metrics add daily/account fields and an explicit gate-failure field.
- New shared `DecisionPolicy` type becomes the contract for train, replay, and live.
- Artifact loading returns a fully specified model+policy bundle, not just raw weights.

## Test Plan
- Dataset tests:
  - no split overlap
  - exact recent-day boundaries
  - `Tier 3` positive labels are non-degenerate across strike and risk fields
- Replay tests:
  - deterministic reruns
  - daily equity curve math
  - baseline cache invalidation on dataset/evaluator/score changes
  - promotion uses `promote_mask`, never `val_mask` or `shadow_mask`
- Artifact tests:
  - saved artifact reloads to identical replay score after process restart
  - manifest mismatch hard-fails
  - reverting code does not corrupt the current best artifact
- Live tests:
  - replay/live intent parity on recorded sessions
  - bracket lifecycle
  - reconnect/orphan handling
  - kill switch
  - daily loss cap
  - EOD flatten
- Rollout acceptance:
  - three consecutive autonomous paper sessions without crash, stale data, or orphaned orders

## Assumptions and Defaults
- Paper trading only; real-money trading is out of scope.
- Starting replay equity is `$50,000`.
- Positioning stays at `1` long SPX option contract max, no pyramiding, one open position at a time.
- `Tier 3` is the only supported v2 training dataset after this plan lands.
- The current `ATM +/- 30` candidate universe remains the supported trading universe for this plan; broader chain exploration is a later iteration.
